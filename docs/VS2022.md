# v1.0.1：VS2022 编译确认

## 结论

现版可以用 VS2022 编译，已实际调用本机 VS2022 安装目录中的 MSBuild.exe 完成 Rebuild，不是仅用 dotnet build 推断。未修改 MES 或 IO 业务逻辑。

实测环境：
- Visual Studio Community 2022 17.14.23
- MSBuild 17.14.23.42201（VS2022 自带）
- .NET SDK 9.0.308；项目目标依然是 net8.0-windows，不是升级为 .NET9
- Configuration=Release，Platform=x86，RuntimeIdentifier=win-x86
- NuGet AntdUI 2.4.4；需要允许 NuGet 恢复依赖
- 实际 Rebuild 返回码 0，输出 TcpServerDmmLite.dll/exe
- 有原 MES 迁移代码的 nullable 注解、未使用变量、未赋值字段警告，无编译错误。本次不扩大修改业务范围消除旧警告。

## 你的电脑怎么编译

1. 安装/更新 VS2022；推荐与实测一致使用 17.14。安装器勾选“.NET 桌面开发”。
2. 安装与 VS 版本匹配的 .NET SDK。目标 net8.0 的官方支持底线是 VS2022 17.8，但不能认为所有新 SDK 都能搭配任意旧 VS。若使用本次实测 SDK 9.0.308，推荐 VS17.14。不要只有运行库而没有 SDK。
3. 解压 Source-VS2022 源码包，打开 TcpServerDmmLite.sln。选择 Release / x86。
4. 右键解决方案→还原 NuGet 程序包，然后“生成→重新生成解决方案”。
5. SDK native 目录应有 x86 N1616.dll、CH367DLL.dll；编译不要求插卡，但运行真实 IO 前必须安装驱动和 VC++2010 x86。
6. 想生成工位免装.NET运行包，在项目目录执行：

```bat
dotnet publish TcpServerDmmLite.csproj -c Release -r win-x86 --self-contained true -o publish
```

自包含只免装 .NET，不免板卡驱动及原生 VC++ 运行库。源码包使用 localhost 示例配置，不含工位实际 IP；实际使用 MES 前必须配置。随包已排除所有厂内 MES XML 模板、历史响应报文和归档ZIP；运行 MES 前可从已有 v1.0.1 运行包复制 Templates；没有借此宣称 MES 现场验收通过。

## 实际执行命令

在项目目录，以本机 VS2022 真实安装路径执行：

```bat
"C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" TcpServerDmmLite.csproj -restore -t:Rebuild -p:Configuration=Release -p:Platform=x86 -verbosity:minimal -nologo
```
